# signature-hero — 핵심 품목을 직접 만지는 인트로 + 히어로

유저가 확정한 기준(2026-09-17): **"선이 아니라 배경을 신경 쓰고, 그 웹사이트의 심장 같은 품목을 넣어 조작되게."**
선·원·진행바 같은 장식은 보조일 뿐이다. 화면을 채우는 것은 배경과 품목이고, 사용자가 손을 대면 품목이 반응해야 한다.

레퍼런스 구현 1호: KEYFORGE 키보드몰 (`assets/keyboard/`, 해설 `references/keyboard.md`).

## 1. 심장 품목 찾기 (코드 쓰기 전에)

사이트 데이터(상품 목록·대표 상품·브랜드 문구)를 읽고 한 문장으로 정한다:
**"이 사이트에서 사람이 손으로 만지는 단 하나의 물건은 ___이고, 그걸 만지는 동작은 ___다."**

- 대표 상품이 여러 개면 매출/브랜드 상징에 가까운 하나. 카테고리 전체가 아니라 **물건 하나**.
- 동작은 실제 세계에서 그 물건을 다루는 동사여야 한다 (키보드=누르다, 물레=돌리다, 세럼=떨어뜨리다).
- 업종별 후보는 `references/archetypes.md` 표에서 고른다. 표에 없으면 같은 방식으로 새로 정의한다.

유저에게 이 한 문장과 선택한 인터랙션을 먼저 짧게 알리고 진행한다 (되돌리기 쉬운 결정이라 허락을 기다리지는 않는다).

## 2. 장면 설계 — 인트로와 히어로는 같은 물건의 두 장면

| | 인트로 (2.5~4초, 건너뛰기 가능) | 히어로 (계속 머무는 첫 화면) |
|---|---|---|
| 물건 | 가까이, 작은 수 (키캡 8개로 브랜드명) | 멀리/크게, 전체 (키보드 한 대가 배경을 채움) |
| 조작 | 누를수록 진행 — 가만히 있으면 자동 진행 | 커서·탭·실제 입력에 즉시 반응, 주변으로 번짐 |
| 배경 | 어둡거나 비어 있다가 진행에 따라 차오름 | 물건 + 따라다니는 빛/그림자, 텍스트 쪽은 그라디언트로 가라앉힘 |
| 끝 | 물건이 움직이며(튀어오름·돌아나감) 페이지가 열림 | 열리는 순간 한 번 반응(물결)해서 두 장면을 잇는다 |

원칙:
- **조작 = 진행.** 인트로의 진행바를 대신하는 것이 물건의 상태 변화다. 진행바는 있어도 얇게.
- **안 만져도 완성.** 자동 진행·자동 반응이 있어야 한다. 조작은 보너스.
- **글씨가 우선.** 히어로 텍스트 뒤는 그라디언트로 눌러서 대비를 확보하고, 물건은 반대편(주로 오른쪽 위)에 둔다.
- **소리는 선택.** 품목에 소리가 자연스러우면(타건·물방울) WebAudio로 합성하고 끄기 버튼을 둔다. 첫 클릭/키 입력 전엔 재생되지 않는다.

## 3. 구현 방식 고르기

1. **DOM + CSS 2.5D 먼저** (레퍼런스 방식): 물건을 div로 만들고 `box-shadow`로 두께, 부모 `perspective` + `rotateX/Z`로 입체.
   요소 수 100개 이하면 충분히 빠르고, 클릭 판정·접근성·반응형이 공짜다.
2. **Canvas 2D**: 입자·액체·연기처럼 수백 개가 움직일 때 (세럼 방울 물결, 커피 김).
3. **WebGL**: 빛·굴절·셰이더가 핵심일 때만. 배경 빛만 필요하면 breathing-light의 `window-light.js`(overlay 모드)를 재사용.
4. 실제 3D 모델이 꼭 필요하면 threeui-scenes. 로딩이 무거우면 인트로에는 쓰지 않는다.

라우팅으로 히어로가 다시 그려지는 사이트(SPA·해시 라우터)는 **렌더 직후 mount를 다시 호출**하고, 전역 리스너는 한 번만 단다.

## 4. 작업 순서

1. 심장 품목·동작 한 문장 → 유저에게 공유
2. `references/archetypes.md`에서 인트로/히어로 조작 방식 선택, 새 업종이면 표에 한 줄 추가
3. 레퍼런스 코드(`assets/keyboard/`) 구조를 따라 작성: 인트로 오버레이(자동 진행·조작 진행·건너뛰기·10초 안전장치) → 히어로 필드(mount 함수·포인터·키보드·물결) → 소리(선택)
4. 사이트 색 변수에 맞춰 칠하기 — 새 CSS 변수·클래스는 접두사를 붙인다(`kf-`처럼). **`--w`, `.line`, `.sec` 같은 흔한 이름은 사이트와 충돌한다**
5. 기존 인트로/히어로 효과가 있으면 걷어내고 교체 (두 개 겹치지 않기)
6. 검증 (아래)

## 5. 검증 (완료 보고 전 필수)

- 인라인한 모든 `<script>` 블록 `node --check` (닫는 script 태그 문자열 주의)
- `node scripts/verify.mjs <URL> <출력폴더>` — 390·320·1440에서 인트로 컷, 인트로가 열리는지, 가로 넘침, 콘솔 에러
- 실제 크롬에서: 키 입력/클릭으로 인트로가 진행되는지, 히어로 위에서 커서·키 입력에 물건이 반응하는지 스크린샷으로 확인
- 터치 기기 안내 문구가 "탭"으로 바뀌는지(`hover:none`), reduced-motion에서 인트로 생략·정적 표시
- **켠/끈 비교**: 히어로 배경을 숨긴 화면과 나란히 봐서 차이가 한눈에 보이는지 (안 보이면 약한 것)
- 함정 목록: `references/pitfalls.md`
